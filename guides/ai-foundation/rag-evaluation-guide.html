Technical Reference

Evaluating a RAG Application: End to End

A reference guide to retrieval and generation evaluation methodology for Retrieval-Augmented Generation systems — covering golden set construction, retrieval metrics, and generation quality assessment.

Prepared by Sunil Kumar · August 2026

Executive Summary

RAG evaluation splits into two independent halves: retrieval (did the system find the right source material?) and generation (did the model write a good answer from it?). Retrieval quality is measured with precision, recall, and ranking metrics (MRR, NDCG) against a labeled "golden set" of question–answer pairs. Generation quality is measured with groundedness (is the answer faithful to its source material?) and correctness (does it match the true answer?). Because these dimensions are independent, a robust evaluation program tracks all of them separately rather than relying on a single end-to-end score.

01The Two Halves of RAG

Every RAG system, agentic or not, does exactly two things in order.

Retrieval
Takes the user's question and searches the knowledge source (vector store, Confluence, PDFs) to pull back relevant chunks of text.
Generation
Takes those retrieved chunks plus the original question and hands them to the LLM, which writes the final answer.
Why split evaluation this way
A system can fail in one half while looking fine in the other — great retrieval with a poor written answer, or a beautifully written answer built on the wrong chunks. Agents don't change this; they just repeat retrieval and generation in a loop, sometimes with extra tool calls in between.

02Building a Golden Set

You can't measure recall or precision without a labeled answer key. That's the golden set — and it's built separately from, and after, ingestion.

  • Ingest normally
    Documents get chunked and embedded into the vector store, independent of any evaluation work.
  • Domain expert supplies realistic questions
    A set of questions real users would actually ask — start with 20–30 and grow over time.
  • Run each question through the live RAG system
    The system returns an answer plus the chunk(s) it used.
  • Expert reviews and confirms correctness
    Faster than writing answers from scratch — the expert is verifying, not searching cold.
  • Lock in the golden set entry
    Store the question, the correct answer text, and the source document + section — deliberately not the chunk ID.
  • Grow it continuously
    Real user complaints about wrong answers become new golden set entries over time, rather than trying to build it all upfront.

03Surviving Re-indexing

Chunk IDs are not stable. Re-chunking or re-embedding shuffles them completely, which breaks any golden set stored by chunk ID.

The fix
Store document name + section (or a content reference) as the source of truth — never the chunk ID itself. At evaluation time, re-derive the current chunk ID fresh by matching text against the document/section. Re-indexing then just means the lookup runs again; the golden set itself never goes stale.

04Precision & Recall, Defined

The two foundational retrieval metrics — everything else on the retrieval side is a variation on these.

Precision
Of the chunks I retrieved, how many were actually relevant?
hits ÷ chunks retrieved
Recall
Of everything relevant that existed, how many did I actually retrieve?
hits ÷ chunks in golden set

Precision is judged from the retrieved side, looking for correctness. Recall is judged from the golden set side, looking for coverage. Same underlying data, opposite direction of checking.

06What Precision Is "Good Enough"?

No universal passing grade — it's a judgment call based on how costly a noisy answer is downstream.

Rough industry range
70–85% precision at top-k is typical for production systems. Below ~60%, hallucination and irrelevant answers tend to creep in. Above ~90%, you may be too conservative and hurting recall.
What actually decides it
How well the generation model ignores irrelevant context, and how costly a wrong answer is for the use case. High-stakes flows (e.g. a support agent guiding troubleshooting) justify aiming higher.

07Ranking Metrics: MRR & NDCG

Precision and recall don't care about order — but generation models tend to weight earlier context more heavily, so order matters in practice.

Mean Reciprocal Rank (MRR)
How far down the list did the first correct chunk appear? Position 1 scores higher than position 5.
NDCG
Normalized Discounted Cumulative Gain — rewards having all correct chunks bunched near the top, not just the first one.
Also worth tracking
Latency and cost per query — a retrieval step that's perfectly accurate but takes eight seconds isn't usable in a real support agent.

09Generation: Groundedness & Correctness

Two distinct dimensions of the written answer — not two names for the same thing.

Groundedness (Faithfulness)
Can every claim in the answer be traced back to the retrieved chunks? Purely about hallucination — has nothing to do with whether the answer is true in the real world.
Correctness
Does the answer match the ground-truth answer a human would consider correct? Doesn't care where the information came from or whether retrieval was even used well.

10The Four Outcome Combinations

Groundedness and correctness are independent axes, so all four combinations are possible.

CorrectIncorrect
Not GroundedGrounded
Grounded + Correct
The goal. Answer is faithful to retrieved context, and that context supports the true answer.
Grounded + Incorrect
Retrieval handed the model bad or outdated information, and it faithfully repeated it.
Not Grounded + Correct
The model got lucky, or answered from its own background knowledge instead of the retrieved chunks.
Not Grounded + Incorrect
The model hallucinating badly — worst-case failure mode.

11Scoring Groundedness & Correctness

In practice, these are scored using LLM-as-a-judge rather than hand-written rules.

  • Judge model compares answer to source
    A strong model — often different from the one that generated the answer, to avoid self-preference bias — is prompted to check whether each claim in the answer is supported by the retrieved chunks (groundedness) or matches the golden answer (correctness).
  • Score or pass/fail with reasoning
    The judge returns a numeric score or a pass/fail verdict, typically along with a short justification, so failures can be audited rather than treated as a black box.
  • Human spot-checks validate the judge
    Judge models have their own blind spots and biases, so a sample of judged outputs is periodically reviewed by a human to confirm the judge's scores are trustworthy.

Two additional generation metrics

Answer Relevancy
Does the answer actually address what was asked? A response can be fully grounded and factually correct while still dodging or under-answering the actual question.
Citation / Attribution Accuracy
If the system shows source links or footnotes, does the cited source actually support the specific claim placed next to it — not just appear somewhere in the answer.

12Evaluation Frameworks

Tooling that packages groundedness, correctness, and relevancy scoring so teams aren't writing judge prompts from scratch.

FrameworkNotes

Vertex AI Rapid Evaluation — example

Scoring a set of RAG responses for groundedness using the Vertex AI Gen AI Evaluation SDK.

# pip install google-cloud-aiplatform[evaluation]
import pandas as pd
from vertexai.evaluation import EvalTask, MetricPromptTemplateExamples

# eval_dataset columns: "prompt", "response", "context"
# - prompt: the user question
# - response: the answer generated by your RAG pipeline
# - context: the chunks retrieved for that question
eval_dataset = pd.DataFrame({
    "prompt": ["What's our policy for damaged goods returns?"],
    "response": ["Damaged goods can be returned within 30 days..."],
    "context": ["Section 2: General returns... Section 5: Damaged goods..."],
})

eval_task = EvalTask(
    dataset=eval_dataset,
    metrics=[
        MetricPromptTemplateExamples.Pointwise.GROUNDEDNESS,
        MetricPromptTemplateExamples.Pointwise.QUESTION_ANSWERING_CORRECTNESS,
        MetricPromptTemplateExamples.Pointwise.QUESTION_ANSWERING_RELEVANCE,
    ],
)

result = eval_task.evaluate()
print(result.summary_metrics)   # aggregate scores across the dataset
print(result.metrics_table)   # per-row scores + judge reasoning
Note
context is what makes this a RAG-aware eval — the judge model checks the response against those retrieved chunks for groundedness, and against a reference answer (if supplied) for correctness.

RAGAS — example

Scoring the same fields with the open-source RAGAS library.

# pip install ragas datasets
from datasets import Dataset
from ragas import evaluate
from ragas.metrics import (
    faithfulness,
    answer_relevancy,
    context_precision,
    context_recall,
)

# Each field is a list, one entry per question
# - question: the user prompt
# - answer: the RAG-generated response
# - contexts: list of retrieved chunks for that question
# - ground_truth: the golden-set answer, for correctness/recall
data = {
    "question": ["What's our policy for damaged goods returns?"],
    "answer": ["Damaged goods can be returned within 30 days..."],
    "contexts": [["Section 2: General returns...", "Section 5: Damaged goods..."]],
    "ground_truth": ["Damaged goods may be returned within 30 days of delivery for a full refund."],
}
dataset = Dataset.from_dict(data)

result = evaluate(
    dataset,
    metrics=[faithfulness, answer_relevancy, context_precision, context_recall],
)

print(result)                 # aggregate scores
print(result.to_pandas())    # per-row breakdown for auditing
Note
faithfulness here is RAGAS's term for groundedness. context_precision and context_recall reuse the retrieval definitions covered earlier in this document, computed automatically from the contexts and ground_truth fields.

13The Human Review Loop

Automated judging reduces manual effort but doesn't eliminate the need for human review.

Recommended cadence
Even with a well-tuned LLM judge in place, teams typically keep a periodic human review loop — spot-checking a sample of judged outputs weekly or per release — to catch cases where the judge model's own biases or blind spots let an error through unflagged.
