§1.1 — LINEAR ALGEBRA

Linear Algebra

The language every layer of a neural network speaks. A model's "knowledge" is, mechanically, just numbers arranged in vectors and matrices.

Every input to a model — a word, a pixel, a user — is encoded as a vector: an ordered list of numbers representing a point in some space. A matrix is a transformation that maps vectors to other vectors — it's how a layer turns "the input representation" into "the output representation." Deep learning, mechanically, is a long chain of matrix multiplications interleaved with non-linear functions.

Core objects & operations
  • Scalar / vector / matrix / tensor — rank-0, rank-1, rank-2, and rank-N arrays. A batch of RGB images is a rank-4 tensor: (batch, height, width, channels).
  • Dot product — measures alignment between two vectors; the core operation inside attention scores and a single neuron's weighted sum.
  • Matrix multiplication — composes transformations; a linear layer is literally y = Wx + b.
  • Transpose, inverse — reorienting a matrix and "undoing" a transformation (when it exists).
  • Eigenvalues / eigenvectors — directions a matrix only stretches, never rotates; the basis of PCA and a way to reason about how gradients propagate through repeated matrix multiplication.
  • Norms (L1, L2) — measures of vector "size." L2 (Euclidean) norm underlies weight decay, gradient clipping, and cosine similarity.
  • Rank & dimensionality — the number of independent directions a matrix's outputs can span; the idea behind LoRA's "low-rank" fine-tuning update.
Notation you'll see everywhere
y = Wx + b — a linear (fully connected) layer
a · b = Σᵢ aᵢbᵢ = |a||b|cos(θ) — dot product; cosine similarity divides this by the norms
softmax(QKᵀ / √d) V — yes, this is attention; it's matrix multiplications end to end
Why it matters downstream

Embeddings are vectors; similarity search is a dot product; attention is matrix multiplication; quantization is compressing the numbers inside these matrices; LoRA fine-tuning exploits the fact that weight updates are often low-rank. You will not escape this layer.

Self-check questions
  1. Why does cosine similarity ignore vector magnitude while the raw dot product doesn't?
  2. If a weight matrix W is m×n, what shape must the input and output vectors be?
  3. What does it mean intuitively for a matrix to be "low rank," and why would a fine-tuning update often be low rank?
  4. Why is matrix multiplication, not addition, the operation that lets a network combine information across all input dimensions?
§1.2 — PROBABILITY & STATISTICS

Probability & Statistics

Models don't output facts — they output distributions. Understanding uncertainty is understanding what a model is actually doing.

An LLM predicting the next token isn't "choosing a word" — it's producing a probability distribution over its entire vocabulary, and something downstream (a sampling strategy) picks from it. Statistics is how you reason about data before training, and how you evaluate whether a model's behavior on a test set is real signal or noise.

Core concepts
  • Random variables & distributions — discrete (categorical, e.g. next-token choice) vs. continuous (Gaussian, e.g. a weight initialization).
  • Conditional probability & Bayes' theorem — P(A|B) = P(B|A)P(A) / P(B); the backbone of how a language model is literally defined: P(next token | previous tokens).
  • Expectation, variance, standard deviation — the average outcome and how spread out outcomes are; loss functions are expectations over a data distribution.
  • Joint / marginal / conditional distributions — how variables relate; marginalizing is "summing out" a variable you don't care about.
  • Entropy & cross-entropy — entropy measures a distribution's inherent uncertainty; cross-entropy measures the gap between a predicted distribution and the true one — this is the standard LLM training loss.
  • KL divergence — asymmetric distance between two distributions; used in RLHF/PPO to keep a fine-tuned policy close to its reference model.
  • Maximum likelihood estimation (MLE) — choosing parameters that make the observed data most probable; the theoretical justification for minimizing cross-entropy loss.
  • Central limit theorem & sampling — why averages over enough samples behave predictably; the basis for trusting evaluation metrics computed on a test set.
The formulas that recur constantly
P(A|B) = P(B|A)·P(A) / P(B) — Bayes' theorem
H(p) = −Σ p(x) log p(x) — entropy: average "surprise" of a distribution
CE(p,q) = −Σ p(x) log q(x) — cross-entropy: standard LLM next-token loss, p = true label, q = model's predicted distribution
D_KL(p‖q) = Σ p(x) log(p(x)/q(x)) — KL divergence: how far q has drifted from p
Why it matters downstream

Temperature, top-k, top-p sampling are all ways of reshaping a probability distribution before drawing from it. Perplexity (a core LLM eval metric) is literally exponentiated cross-entropy. Hallucination can partly be understood as a model confidently sampling from a poorly-calibrated distribution.

Self-check questions
  1. Why is minimizing cross-entropy loss equivalent to maximum likelihood estimation?
  2. What does a temperature of 0 do to a softmax output distribution, mechanically?
  3. Why is KL divergence not symmetric, and why does that matter when it's used as a regularizer in RLHF?
  4. If a model is "well calibrated," what does that mean about its predicted probabilities versus its actual accuracy?
§1.3 — MACHINE LEARNING CONCEPTS

Machine Learning Concepts

The learning loop itself: how a model turns data and a loss signal into better parameters, and how to tell if it's actually learning the right thing.

The core learning loop
  • Supervised / unsupervised / self-supervised / reinforcement learning — labeled targets, no targets, targets derived from the data itself (next-token prediction is self-supervised), and reward-driven learning (RLHF).
  • Loss function — a single number quantifying how wrong the model's predictions are; the thing gradient descent tries to minimize.
  • Gradient descent & backpropagation — backprop computes how much each parameter contributed to the error (via the chain rule); gradient descent nudges each parameter in the direction that reduces the loss.
  • Learning rate — the step size of each update. Too high: training diverges. Too low: training crawls or gets stuck.
  • Optimizers — SGD, Momentum, Adam/AdamW — refinements on plain gradient descent that adapt the step size per parameter and smooth out noisy updates. AdamW is the default for training transformers.
Generalization & the bias–variance trade-off
  • Overfitting — the model memorizes training data and fails on new data (low bias, high variance).
  • Underfitting — the model is too simple to capture the pattern at all (high bias).
  • Regularization — L1/L2 weight penalties, dropout, early stopping — techniques that trade a little training accuracy for better generalization.
  • Train / validation / test split — never tune decisions on the data you'll report final numbers on.
  • Cross-validation — rotating which slice of data is held out, to get a more reliable performance estimate on small datasets.
Evaluation basics
  • Accuracy, precision, recall, F1 — precision penalizes false positives, recall penalizes false negatives; F1 balances both. Matters a lot when classes are imbalanced.
  • Confusion matrix — the full breakdown of predicted vs. actual classes that those metrics are computed from.
  • ROC-AUC — how well a classifier ranks positives above negatives across all thresholds.
  • Bias–variance trade-off — the meta-pattern behind all of the above: model capacity trades off between fitting training data well and generalizing to new data.
The update rule
θ ← θ − η · ∇L(θ) — gradient descent: θ = parameters, η = learning rate, ∇L = gradient of the loss
Precision = TP/(TP+FP)    Recall = TP/(TP+FN)    F1 = 2·(P·R)/(P+R)
Common trap

A model with 99% accuracy on a dataset where 99% of examples are one class has learned nothing — this is why precision/recall (or a confusion matrix) matter more than accuracy alone once classes are imbalanced, which is the normal case for real-world data like fraud detection or safety classifiers.

Why it matters downstream

Every training run in Stage 3 — pretraining, fine-tuning, LoRA, RLHF — is this same loop (forward pass → loss → backward pass → optimizer step) at increasing scale. Overfitting reframes as "the model memorized its training data" — relevant to both eval integrity and privacy/leakage concerns in production LLMs.

Self-check questions
  1. Why does backpropagation need the chain rule, and what would break without it in a deep network?
  2. You add more layers and training loss keeps dropping but validation loss starts rising. What's happening, and what are two ways to address it?
  3. Why is AdamW generally preferred over plain SGD for training transformers?
  4. Give an example where recall matters far more than precision, and one where the reverse is true.
