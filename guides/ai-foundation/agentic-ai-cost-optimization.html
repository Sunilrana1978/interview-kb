01

Progressive Disclosure over Full Context

Agent Skills · scoped AgentTool

Loading every tool schema and policy document into the orchestrator's system prompt bloats context on every turn — even when most of it is irrelevant to the request at hand.

from google.adk.agents import LlmAgent
from google.adk.tools.agent_tool import AgentTool

knowledge_agent = LlmAgent(
    name="knowledge_agent",
    model="gemini-2.5-flash",
    description="Answers questions using the internal knowledge base.",
    instruction="""You answer questions using the retrieve_docs tool only.""",
    tools=[retrieve_docs_tool],
)

status_agent = LlmAgent(
    name="status_agent",
    model="gemini-2.5-flash",
    description="Looks up status/state for a given record ID.",
    tools=[get_status_tool],
)

# orchestrator only ever sees the one-line `description` of each sub-agent
root_agent = LlmAgent(
    name="orchestrator",
    model="gemini-2.5-flash",
    instruction="""Route to knowledge_agent or status_agent based on intent.""",
    tools=[AgentTool(agent=knowledge_agent), AgentTool(agent=status_agent)],
)
Why it works — context cost scales with what's used per turn, not the total size of the tool/policy catalog. A skill-file variant (frontmatter summary + load_skill(name) tool for the full body) applies the same idea to long policy documents.
02

Prompt Caching

Native context caching · ContextCacheConfig

Static content — tool reference docs, few-shot examples, policy guides — gets re-sent and re-billed on every call if it isn't cached.

from google.adk import Agent
from google.adk.apps.app import App
from google.adk.agents.context_cache_config import ContextCacheConfig

root_agent = Agent(
    name="status_agent",
    model="gemini-2.5-flash",
    # static portion — tool reference + few-shot examples — is what gets cached
    instruction=f"""{TOOL_REFERENCE_DOC}\n{LONG_FEW_SHOT_EXAMPLES}""",
    tools=[get_status_tool],
)

# configured once at the App level — applies to every agent in the app
app = App(
    name="status-app",
    root_agent=root_agent,
    context_cache_config=ContextCacheConfig(
        min_tokens=2048,
        ttl_seconds=600,
        cache_intervals=5,
    ),
)
Why it works — only the live turn is billed at full price; the static block is cached and reused automatically. No manual Vertex CachedContent handle to manage.
03

Parallel, Isolated Sub-Agents

ParallelAgent vs SequentialAgent

In a sequential chain, every downstream agent inherits the full context of everything upstream — token cost and latency compound with chain length.

from google.adk.agents import ParallelAgent, SequentialAgent

# independent lookups → isolated context each, run concurrently
parallel_lookup = ParallelAgent(
    name="parallel_lookup",
    sub_agents=[status_agent, knowledge_agent],
)

# genuinely dependent flow → stays sequential
resolve_or_escalate = SequentialAgent(
    name="resolve_or_escalate",
    sub_agents=[knowledge_agent, escalation_agent],
)
Why it works — each parallel sub-agent starts fresh with just what it needs; the orchestrator merges results afterward. Smaller aggregate token footprint despite more model calls, plus lower wall-clock latency.
04

Model Tiering per Sub-Agent

Right-sized model per step

Routing a high-frequency, low-complexity step (like intent classification) through your strongest — and most expensive — model wastes spend.

router_agent = LlmAgent(
    name="router",
    model="gemini-2.5-flash",  # cheap, fast — just classifies intent
    instruction="Classify intent as one of: lookup, generate, escalate.",
)

synthesis_agent = LlmAgent(
    name="synthesizer",
    model="gemini-2.5-pro",  # reserved for real generation
    tools=[retrieve_docs_tool],
)
Why it works — you pay for reasoning power only where it's actually needed, not uniformly across every step in the pipeline.
05

Trim Conversation History

before_model_callback

Left unmanaged, session state grows unbounded turn over turn — every prior message re-enters context on every subsequent call.

from google.adk.agents.callback_context import CallbackContext

def trim_history_before_model(callback_context: CallbackContext, llm_request):
    """Keep only the last N turns before sending to the model."""
    MAX_TURNS = 6
    history = callback_context.state.get("conversation_history", [])
    if len(history) > MAX_TURNS:
        callback_context.state["conversation_history"] = history[-MAX_TURNS:]
    return None

trimmed_agent = LlmAgent(
    name="chat_agent",
    model="gemini-2.5-flash",
    before_model_callback=trim_history_before_model,
)
Why it works — caps history size before each call, keeping long-running sessions from quietly becoming the biggest driver of per-turn cost.
06

Structured Tool Outputs, Not Prose

Compact JSON over natural language

Tool results re-enter context on the next turn — a prose explanation costs meaningfully more tokens than the same information as structured data.

def get_status(record_id: str) -> dict:
    """Returns compact structured status instead of a prose explanation."""
    result = call_status_api(record_id)
    return {
        "id": record_id,
        "stage": result["stage_code"],   # e.g. "CONFIRMED"
        "updated": result["last_updated"],
    }
    # NOT: f"The record {record_id} is currently in the Confirmed stage as of..."
Why it works — the model can still narrate results naturally to the end user at the final step, without that narration being what gets carried in context turn after turn.
