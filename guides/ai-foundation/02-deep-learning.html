STAGE 02

Master Deep Learning

This stage is one continuous story: a plain neural network can't handle sequences well → RNNs add memory but can't parallelize or see far back → attention lets any position look directly at any other position → the transformer builds an entire architecture around attention. Every LLM you'll study in Stage 3 is a transformer.

§2.1 — NEURAL NETWORKS

Neural Networks

Stacked linear layers plus non-linearities, trained end to end by gradient descent. Every architecture in this stage is a variation on this base.

A neuron computes a weighted sum of its inputs, adds a bias, and passes the result through a non-linear activation function. Stack many neurons into a layer, stack many layers into a network, and you get a multi-layer perceptron (MLP) — a universal function approximator, given enough width and depth.

Core components
  • Activation functions — ReLU (fast, sparse, default for most hidden layers), GELU (smoother, used in transformers), sigmoid/tanh (mostly legacy, saturate and cause vanishing gradients), softmax (turns logits into a probability distribution at the output).
  • Forward pass — input flows through the layers to produce a prediction.
  • Backward pass (backpropagation) — the chain rule propagates the loss gradient back through every layer to compute how much each weight should change.
  • Weight initialization — random, but carefully scaled (e.g. Xavier/He init) so signal neither explodes nor vanishes across many layers.
  • Batch normalization / layer normalization — rescale activations mid-network to stabilize training; transformers use layer norm specifically because it works independent of batch size and sequence position.
  • Dropout — randomly zeroes activations during training to prevent co-adapted, overfit features.
  • Vanishing / exploding gradients — in deep networks, gradients can shrink toward zero or blow up as they propagate backward through many layers, stalling learning. Residual connections and normalization exist largely to fight this.
  • Residual (skip) connections — add a layer's input directly to its output (x + F(x)), giving gradients a direct path backward. What makes networks with 96+ layers (like GPT-scale transformers) trainable at all.
The neuron, generalized
a = f(Wx + b) — f is the activation function; without it, stacked layers would collapse to one linear layer
ReLU(x) = max(0, x)    GELU(x) ≈ x·Φ(x) Φ = standard normal CDF
Common trap

Without a non-linear activation, no depth of stacked linear layers can do more than a single linear layer — matrix multiplications compose into just another matrix multiplication. Non-linearity is what gives depth its power.

Self-check questions
  1. Why does removing all activation functions collapse a deep network to something equivalent in expressive power to one layer?
  2. What specific problem do residual connections solve in very deep networks?
  3. Why do transformers use layer normalization rather than batch normalization?
§2.2 — CNNS

Convolutional Neural Networks

The architecture built for spatial, local structure — images, and by extension anything with a grid-like layout.

Instead of connecting every input to every neuron (as an MLP does), a CNN slides a small filter (kernel) across the input, learning local patterns — edges, textures, shapes — that compose into higher-level features as you stack layers deeper.

Core components
  • Convolution — a small learned filter slides over the input, computing a dot product at each position; produces a feature map.
  • Stride & padding — stride controls how far the filter moves each step (downsampling); padding controls whether the output shrinks at the edges.
  • Pooling (max/average) — downsamples feature maps, adding translation invariance and reducing compute.
  • Parameter sharing — the same filter is reused across the entire image, which is why CNNs need far fewer parameters than a fully-connected network for the same input size.
  • Receptive field — how much of the original input a given neuron "sees"; grows with depth and stride.
  • Feature hierarchy — early layers learn edges/colors, middle layers learn textures/parts, late layers learn whole objects.
Why it matters downstream

CNNs matter less for text LLMs directly, but the underlying idea — local structure, parameter sharing, hierarchical features — reappears in multimodal models (vision encoders feeding into LLMs, e.g. GPT-4V-style architectures) and in some efficient-attention variants inspired by convolution's locality.

Self-check questions
  1. Why does parameter sharing make CNNs far more parameter-efficient than a fully-connected network on images?
  2. What does "receptive field" mean, and how do stride and depth affect it?
§2.3 — RNNS

Recurrent Neural Networks

The first serious attempt at handling sequences — and the architecture the transformer was invented to replace.

An RNN processes a sequence one element at a time, carrying a hidden state forward as memory of everything seen so far. That sequential dependency is exactly what made RNNs hard to parallelize and prone to forgetting long-range context.

Core concepts
  • Hidden state — a running summary vector updated at every timestep, carrying information forward.
  • Sequential processing — step t depends on step t−1, which is why RNNs can't be parallelized across the sequence dimension the way transformers can.
  • Vanishing gradients over time — the same instability problem from §2.1, but along the time axis: gradients from far-future losses shrink to near-zero by the time they reach early timesteps, so vanilla RNNs struggle to learn long-range dependencies.
  • LSTM / GRU — gated variants (forget/input/output gates) designed specifically to preserve gradient flow over longer sequences.
  • Bidirectional RNNs — process the sequence both forward and backward to use future context, at the cost of no longer being usable for pure left-to-right generation.
  • Sequence-to-sequence (encoder–decoder) — an encoder RNN compresses the input into a fixed context vector; a decoder RNN generates the output from it. The bottleneck of a single fixed vector is exactly the problem attention was invented to solve.
Why RNNs lost to transformers

Two structural limits: (1) sequential computation means no parallelism across timesteps during training — painfully slow at scale; (2) the fixed-size hidden state is an information bottleneck, so long-range dependencies degrade no matter how good the gating is. Attention fixes both.

Self-check questions
  1. Why can't RNN training be parallelized across the sequence dimension the way transformer training can?
  2. What specific problem do LSTM gates solve that a vanilla RNN cell doesn't?
  3. What is the encoder–decoder "bottleneck," and how does it motivate attention?
§2.4 — ATTENTION MECHANISM

Attention Mechanism

Instead of compressing a whole sequence into one vector, let every output position look directly at every input position and decide what's relevant.

Attention computes, for each token, a weighted combination of every other token's representation — where the weights are learned and depend on the content itself. This is the single mechanism that made both long-range dependency modeling and full parallelization possible at the same time.

Query, Key, Value — the core abstraction
  • Query (Q) — "what am I looking for?" — a projection of the current token.
  • Key (K) — "what do I contain?" — a projection of every token being attended to.
  • Value (V) — "what do I actually pass along?" — the content that gets mixed together once attention weights are computed.
  • Attention score — the dot product of a Query with each Key, measuring relevance; scaled down and passed through softmax to become weights that sum to 1.
  • Self-attention — Q, K, and V all come from the same sequence (tokens attending to other tokens in the same input).
  • Cross-attention — Q comes from one sequence, K/V from another (e.g. a decoder attending to an encoder's output).
  • Multi-head attention — run several attention operations in parallel with different learned projections, so different heads can specialize (one head might track syntax, another coreference, another position).
  • Causal (masked) attention — for autoregressive generation, mask out future positions so a token can only attend to itself and what came before — this is what makes GPT-style left-to-right generation valid.
Scaled dot-product attention
Attention(Q,K,V) = softmax(QKᵀ / √d_k) · V
— QKᵀ scores relevance between every pair of tokens; √d_k prevents scores from growing too large as dimension increases (which would push softmax into tiny gradients); softmax turns scores into weights; multiplying by V blends the values accordingly.
Why it matters downstream

Attention's O(n²) cost in sequence length n is the reason context-window scaling is hard (Stage 3), and the reason the KV cache exists (Stage 3) — caching the K and V projections so they aren't recomputed for every new generated token.

Self-check questions
  1. What's the intuitive difference between what Query, Key, and Value each represent?
  2. Why divide by √d_k before the softmax?
  3. Why does causal masking matter for a model that generates text left-to-right, and what would break without it?
  4. Why is multi-head attention more expressive than a single attention operation with a larger dimension?
§2.5 — TRANSFORMERS

Transformers

The architecture that assembles attention, feed-forward layers, residuals, and normalization into the backbone of every modern LLM.

Anatomy of a transformer block
  • Multi-head self-attention — lets tokens exchange information (§2.4).
  • Feed-forward network (FFN/MLP) — applied identically to each position, expanding then projecting back down (typically 4× the hidden size); where much of the model's factual "storage" is believed to live.
  • Residual connections + layer norm — around both the attention and FFN sub-layers, stabilizing training at depth (§2.1).
  • Positional information — attention alone has no notion of order, so position must be injected explicitly (full treatment in Stage 3).
Encoder, decoder, and encoder–decoder variants
TypeAttention patternUsed forExamples
Encoder-onlyBidirectional (sees full input)Understanding/classification tasks, embeddingsBERT
Decoder-onlyCausal / masked (left-to-right)Text generationGPT family, Llama, Claude
Encoder–decoderBidirectional encoder + causal decoder + cross-attentionTranslation, summarizationT5, original Transformer

Almost every LLM you'll interact with day to day is decoder-only — the architecture that dominates because it's simplest to scale and naturally suited to open-ended generation.

One block, end to end
x' = x + MultiHeadAttention(LayerNorm(x))
out = x' + FFN(LayerNorm(x'))
Stack N of these blocks (N in the dozens to low hundreds for frontier models) and you have a transformer.
Why it matters downstream

Everything in Stage 3 — tokenization feeds this, embeddings and positional encoding become its input, training adjusts every weight in it, inference runs it forward one token at a time, quantization compresses its weights, and MoE swaps its FFN layers for sparse expert routing.

Self-check questions
  1. Why do almost all modern LLMs use a decoder-only architecture rather than encoder–decoder?
  2. What is the FFN sub-layer doing that self-attention isn't?
  3. Where exactly do residual connections sit relative to attention and the FFN in a standard block ("pre-norm" transformers)?
