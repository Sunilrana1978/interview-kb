Gemini Enterprise — Evaluation Methodology

Approach for validating search/answer quality against a client-provided golden test set

1. Objective

To demonstrate to the client that the new Gemini Enterprise search app performs at an acceptable quality bar before go-live, using their own golden set — questions paired with expected answers and expected source citations — run automatically against the live application, with results distilled into a scorecard.

2. Inputs required from the client

FieldDescription
QuestionA realistic user query, ideally 40–100+ questions spanning the different topic areas / data sources in scope, not cherry-picked.
Expected answerThe client's "golden" / ground-truth answer to compare generated output against.
Expected citation(s)The specific document(s) or source(s) the answer should be grounded in.

3. Evaluation metrics

1. Retrieval accuracy

Did the system retrieve the correct source document(s) at all — measured as a hit rate (e.g. precision at top-k).

Custom check — compare returned source IDs against expected citations. Not covered by the managed evaluation service.

2. Citation correctness

Even where the system found the right general area, did it cite the exact document/page the client expected — catches cases where the answer sounds right but points to the wrong source.

Custom check — same source-ID comparison logic as retrieval accuracy.

3. Answer correctness

Semantic match between the generated answer and the expected answer — scored on a scale (e.g. 0–1), not exact string matching, since correct answers can be worded very differently.

Handled by Google's Gen AI Evaluation Service — LLM-as-judge scoring.

4. Groundedness / faithfulness

Does the generated answer actually stay true to what the cited source says — catches hallucination even when the final answer happens to sound plausible.

Handled by Google's Gen AI Evaluation Service — built-in "grounding" metric, purpose-built for RAG systems.

4. Division of labor: managed service vs. custom scripting

Custom scripting (build)

  • Loop through golden set, call the live Gemini Enterprise API per question
  • Capture generated answer + returned citations/source IDs
  • Compare returned source IDs vs. expected citations → retrieval accuracy & citation correctness scores
  • Format captured output + golden reference into the input structure the Gen AI Evaluation Service expects

Google Gen AI Evaluation Service (reuse)

  • Takes prompt, retrieved context, and reference ("golden") answer as input
  • Built-in GROUNDING metric — checks factuality/consistency against ground truth, purpose-built for RAG
  • LLM-as-judge scoring for answer correctness — no need to build a custom scoring/comparison model
  • Does not natively score pure retrieval correctness — that stays on the custom side

6. Scorecard output (what the client sees)

Two levels of reporting:

LevelContents
Per-questionQuestion, expected vs. actual answer, expected vs. actual citation, pass/fail per metric
AggregateRetrieval accuracy %, citation correctness %, answer correctness %, groundedness %, overall pass rate, list of specific failures with reasoning

Suggested recommended threshold to discuss with the client: ~85% aggregate pass rate before go-live — to be adjusted based on risk tolerance and criticality of the use case.
